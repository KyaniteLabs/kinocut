**Status:** ready-for-agent

## Test seams (highest, existing first)

One compiler seam: **propose → validate → approve → render** a `360_assembly_plan`.

Hook it through existing surfaces only:

- **Intent** — `video_intent` with `goal=` emits the plan (no new MCP name).
- **Review** — same approve/reject contract as shorts/EDL review.
- **Render** — existing cutfile/workflow render plus composite split/PiP and trim/merge.
- **Director** — one `propose(...)` adapter; must not mutate an approved plan (same rule as remote provider adapters).

Do not add a 197th public tool. Do not extend Anthropic-only vision QC.

## Problem Statement

I record on an Insta360 X4 with one lens on me and one on the work (screens when I code in public, the table when I pull tarot). The camera already saw both angles. I cannot turn that into a watchable video without sitting in Insta360 Studio and aiming by hand. I do not know yaw and pitch. I want the system to find the two cameras, show me a storyboard, let me (or an agent) pick split / switch / PiP / single, and then format a normal 16:9 or 9:16 edit. If a local or cloud model has better taste, it should fill the same plan — not secretly publish, and not lock me to one vendor.

## Solution

Export a stitched 360 MP4 from Insta360. Kinocut treats that file as two or more virtual cameras, writes a reviewable assembly plan, shows stills, waits for approval, then renders with FFmpeg `v360` and the existing split/PiP/switch tools. A pluggable director (Ollama/local first, cloud only if I opt in) may propose the plan. Kinocut always validates, renders, quality-gates, and receipts. The model never writes pixels.

## Implementation Decisions

- Build a 360 assembly compiler (plan + cameras + storyboard + render), not a new NLE and not an Insta360 stitcher.
- Plan artifact kind is `360_assembly_plan`, schema version 1, frozen JSON, statuses `proposed` then `approved` or `rejected`.
- Cameras are id, yaw, pitch, roll, fov. Windows may override plan-level layout.
- Presets: desk = talent yaw 0 + screens yaw 180, default split. Table = talent + table pitched down, default switch.
- Layouts: single, split, pip, switch.
- Writers: heuristic, single, model. Model is a director adapter: propose(stills, cameras, duration, output).
- Director selection via explicit fields or env (director id, model, base URL). Local OpenAI-compatible first. Cloud requires allow_cloud.
- Do not hardcode Anthropic into vision QC for this. Do not call the director at render time.
- Public surface: overload video_intent goal= plus existing review and render. Stop and ask before adding a public name.
- FFmpeg v360 for extracts. Existing composite for split/PiP. Trim+merge for switch. Escape all filter values. Custom errors only. Timeouts on subprocesses.
- Probe: equirect about 2:1 and/or spherical metadata. .insv fails closed.
- QC on render with default quality gate 80. Human visual/audio still required.
- Keep modules at or under 800 LOC and functions at or under 80. No published claims bump.

Prototype plan shape (decision, not a demo):

```json
{
  "artifact_kind": "360_assembly_plan",
  "schema_version": 1,
  "projection": "equirect",
  "layout": "split",
  "cameras": [
    { "id": "talent", "yaw": 0, "pitch": 0, "roll": 0, "fov": 90 },
    { "id": "screens", "yaw": 180, "pitch": 0, "roll": 0, "fov": 90 }
  ],
  "writer": { "kind": "heuristic", "provider": null, "model": null },
  "status": "proposed"
}
```

## Testing Decisions

Test external behavior: given a source and a goal, does the plan validate, does review gate render, do the two hemispheres stay distinct, does the director plug refuse bad JSON and refuse cloud without opt-in.

- Synthetic 2:1 color-hemisphere fixture (not real X4 media) for extract and split.
- Schema reject cases (unknown layout, end before start, missing cameras).
- Heuristic desk/table defaults.
- Approve then file exists; no approve then error.
- Fake local director returns a valid plan; invalid JSON is unavailable; heuristic still works.
- Cloud without opt-in is denied even if a key is present.
- Intent goal still leaves tool count at 196.
- Import identity kinocut.Client is mcp_video.Client still holds.

Prior art: product-finish goal to cutfile to approve EDL; shorts review/package fail-closed; remote adapters that cannot change an approved plan; TTS backend detect honesty.

## Out of Scope

- Decoding or stitching .insv.
- Continuous auto-steer or face-orbit around the sphere.
- Phase 4 TTS/VLM/generative execute restaff (director proposes a plan only).
- Silent mutation apply.
- Signed MCPB, directories 88, launch 90.
- Public claims or version bump.
- A 197th MCP or CLI verb.
