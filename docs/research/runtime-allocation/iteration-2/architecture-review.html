Make the existing modules deeper

Five opportunities grounded in actual execution friction, recent media hot spots and ADRs. This report proposes directions, not detailed interfaces or a blanket rewrite.

CAS availability lifecycleShared quality evidenceMedia operation lifetimeTransport-free detached completionWorkflow op knowledge
What earns priority: replicated correctness failures, repeated decoder work and caller knowledge that belongs inside an existing module. Stable compatibility facades and useful mixins stay; fewer files are not the goal.

1. CAS availability lifecycle

Strong

kinocut/projectstore/cas.py:30–90; cas_gc.py:121–144

Problem

Ingest treats an existing manifest as available; resolve treats any historical deletion as permanently unavailable. Re-ingest after GC returns success, then resolution fails in an executed reproduction.

Deepening opportunity

Deepen one CAS lifecycle module so ingest, resolve and collection use the same availability interpretation. Preserve immutable manifests and append-only provenance. Decide explicitly between recorded, verified restoration and rejected re-ingestion.

Before

Ingest: manifest = live
↓
Resolve: past deletion = dead
↓
GC: separate live-set logic

After

Ingest / resolve / GC adapters
↓
CAS lifecycle module
↓
Verified availability + provenance

Locality, leverage and tests

Locality for availability transitions; leverage across source assets and derived indexes. The interface is the test surface: ingest → collect → re-ingest → reopen → resolve exact bytes; failed and concurrent restoration. Deleting the deep module would scatter the invariant back into three callers.

2. Shared quality evidence

Strong

kinocut/quality_guardrails.py:114–289; design_quality/guardrails/probe.py:25–114; analysis.py:178–230

Problem

Technical and design checks repeatedly probe/decode the same media and interpret partial results differently. A same-path replacement keeps stale measurements. Identical gray 8-bit and 10-bit fixtures receive pass versus blown-highlights judgments.

Deepening opportunity

Deepen one media-evidence module at the existing runtime seam. Hide sampling, units, color domain, decode coverage, availability and cache invalidation. Technical delivery requirements and creative advice consume the same facts with distinct policies.

Before

Technical checks → own decode
↓
Design checks → own decode
↓
Independent scores / missing data

After

Technical + creative policies
↓
Media-evidence module
↓
One verified source snapshot

Locality, leverage and tests

Locality for measurement errors and leverage from one analysis reused by several checks. Test externally meaningful bit-depth/range equivalence, missing evidence, same-path changes and bounded decode counts. Preserve ADR-0004 mixins internally. Deleting the module would distribute decode and unit contracts again.

3. Media operation lifetime

Strong

kinocut/ffmpeg_helpers.py:73–115,287–478; workflow/executor.py:119–125; engine_convert.py:75–95

Problem

Callers must know when to reset ambient input/output records, which runner bounds logs and whether output publication is staged. An actual conversion failure altered an existing destination. Cancelled jobs can keep rendering after runner identity is discarded.

Deepening opportunity

Deepen the existing media-execution module with operation-owned lifetime, bounded subprocess handling and staged verification/publication. Integrate requested cancellation with observed exit. Keep compatibility adapters and existing verified process-group safeguards.

Before

Caller resets ambient state
↓
Engine chooses runner + staging
↓
Cancel state ≠ stopped process

After

Direct / workflow adapters
↓
Media execution module
↓
Bounded lifetime + verified publish

Locality, leverage and tests

Locality for timeout, cancellation and publication invariants; leverage across media writers. Test sequential/nested/concurrent direct calls without harness resets, hardlinks, noisy child processes and preservation of prior output after failure. Deleting this depth would return lifecycle obligations to every engine.

4. Transport-free detached completion

Strong

kinocut/projectstore/render_runner.py:37–108; server_tools_workflow.py:72–142; render_jobs.py:183–219

Problem

Detached execution imports an MCP tool handler, interprets its transport envelope, then strips success before recording lineage. Cold worker import measured 624ms; transport registration is unnecessary execution knowledge.

Deepening opportunity

Let MCP and detached-render adapters both call the workflow engine. Deepen detached completion around lineage, errors and terminal recording. Transport envelopes stay in the MCP adapter. Preserve the existing locked success/event commit and its documented crash limitations.

Before

Detached worker
↓
MCP envelope adapter
↓
Workflow engine → envelope cleanup

After

MCP + detached adapters
↓
Workflow engine
↓
Completion: lineage + terminal state

Locality, leverage and tests

A real seam already has two adapters. Deleting envelope pass-through removes complexity; deep completion gives locality to provenance-before-success and leverage for future durable callers. Test job outcomes through the job-facing interface plus separate MCP envelope contracts. Do not promise a cold-start saving until measured after implementation.

5. Workflow op knowledge

Worth exploring

kinocut/workflow/ops.py:96–157; validator.py:194; planner.py:133; executor.py:591,607,704

Problem

Composite and burn-in input shapes are understood separately by adapters, validation, planning and execution. Adding a vetted operation requires coordinated changes in several modules.

Deepening opportunity

Deepen the existing op module around declared refs, confined validation and binding. Common orchestration still owns workspace confinement, ordering and receipts. Preserve ADR-0007 bounded allowlist and signature introspection; no speculative plugin framework.

Before

Op adapter
↓
Validator / planner switches
↓
Executor / hash switches

After

Validator / planner / executor
↓
Deep op module
↓
Declared refs + binding

Locality, leverage and tests

Locality for operation-shape knowledge; leverage when real new ops are needed. Interface tests verify identical refs are validated, hashed, planned and invoked, including malicious nested refs. Deleting the deep module would scatter these rules back into callers. Deprioritize if no op expansion is planned.

Top recommendation

Repair the demonstrated CAS disagreement first. Then deepen shared quality evidence: later ML and editorial reasoning need trustworthy, reusable observations. Detached completion is the smallest architecture refactor if a narrow first step is preferred.

Existing Revideo transactions already hide rollback, observed-media verification and atomic publication behind a useful interface. Use that depth as evidence; do not reorganize it merely because it has many private helpers.

No candidate requires abandoning ADR-0001 stable facades, ADR-0002 central FFmpeg helpers, ADR-0003 transport separation, ADR-0004 guardrail mixins, ADR-0007 bounded operations, or ADR-0008 append-only editing provenance.
