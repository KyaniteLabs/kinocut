# Audio timeline fixture correction after hosted CI

Head `ee7c5d6e823223673a382bda8a3a11349aaa68b1` passed twelve of thirteen
checks. [Hosted run 36775058293](https://github.com/KyaniteLabs/kinocut/actions/runs/36775058293)
passed lint but its test suite reported **1 failed, 7,425 passed, 46 skipped,
164 deselected, 8 warnings** in 881.80 seconds. The accessible annotation
identified `test_source_audio_stays_relative_to_picture_origin[1-0]`: RMS at
0.65 seconds was -200 dB where the fixture expected audible source speech.
The runner used FFmpeg/FFprobe 6.1.1-3ubuntu5, Python 3.14.7 and pytest 9.1.1.

The failure came from an unverified fixture-origin assumption. FFmpeg 6's
default output synchronization filled the intended one-second picture delay
with extra frames. A native comparison reproduced the resulting actual
picture start of zero, duration four seconds and 100 frames; the source voice
remained at its original time. The mixer correctly preserved that actual
timeline. FFmpeg 7's default fixture instead started picture at one second,
with three seconds and 75 frames.

The test now requests `-fps_mode passthrough` and asserts the input picture's
actual origin and duration before measuring output audio. Both versions then
produce the intended one-second picture start, three seconds and 75 frames.
Audibility thresholds, silence windows and equality of decoded source/output
picture frames remain unchanged. This correction changes a test fixture and
changelog; the production mixer implementation is unchanged.

## Native comparison and scope

[Generator metadata](generator-comparison.json) records both versions with
default and explicit passthrough synchronization. Built-in MPEG-4 encoding
isolates synchronization behavior without requiring libx264 in the minimal
source build; it is not a libx264 benchmark. [Native mixer observations](native-mixer-comparison.json)
record four independent native FFmpeg 6 render/AAC-encode/staged-decode cases:
the default six-generated four-second source keeps speech at 1.65 seconds;
the other three-second sources keep speech at 0.65 seconds relative to picture.
FFmpeg 7 measures the decoded RMS. Two H.264 controls generated by FFmpeg 7
also pass actual FFmpeg 6 mixing and staged audio decoding.

The complete FFmpeg 7 mixer set passed **39 tests in 31.16 seconds**. The
minimal native FFmpeg 6 mixer set passed **37 tests, 2 deselected, in 20.18
seconds**, using FFmpeg 7 for fixture generation and the RMS oracle. The two
excluded cases need sidechain compression or MP3 demuxing/decoding absent
from this temporary build; initial attempts failed for those setup limitations.
Hosted test selection remains unchanged. The earlier five-case primary
FFprobe 6 comparison used FFmpeg 7 rendering and is separate evidence.

Native source is official tag `n6.1`, commit
`d4ff0020b40b524a490cf62eccbd3a318f4c0e58`, built with GCC 14 and two compile
workers. The component-enabled FFmpeg binary has SHA-256
`7ad97d2dd2eae900938d0f905934c4dd6077603fcd28a879b50dfa1e862f3788`;
FFprobe has `8e1e2ed4b6c3bda15278e868f1e1cd0a8fccc346ffddfc1857494db96dd5db0f`.
This is a scoped native comparison, not complete FFmpeg 6 platform acceptance.
The corrected published head needs its own local full gate and hosted CI;
the failed head's twelve successes do not validate the correction.
