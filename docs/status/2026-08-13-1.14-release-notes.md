# Kinocut 1.14.0 release notes

**Published:** 2026-08-13 — PyPI `kinocut==1.14.0`, npm `kinocut@1.14.0`, GitHub Release `v1.14.0`.

**Published surface:** 196 MCP tools / 167 CLI commands (unchanged from 1.13.4).

**Compat:** `mcp-video==1.6.9` installs `kinocut==1.14.0`.

## Three agent-facing bullets

1. **What agents can do now** — Turn a **stitched equirect 360 MP4** (Insta360, Ricoh Theta, GoPro MAX, DJI Osmo 360, …) into a reviewable two-cam edit: `video_intent` `goal=` writes a `360_assembly_plan`, `video_review_decide` approves or rejects, then FFmpeg `v360` renders split / switch / PiP / single. No new MCP name. Raw `.insv` / `.360` fail closed.
2. **What got safer / faster** — Single-pass 360 `filter_complex` keeps source audio; merge probes each clip honestly; sampled QC (`max_analyze_seconds`); SHA-256 path/mtime cache; lazy `import kinocut` / CLI / `Client.search_tools`; doctor skips unused `npx --yes`.
3. **Compat** — `mcp-video==1.6.9` installs `kinocut==1.14.0`. Counts stay **196 / 167**. Prefer `kinocut` / `kino` for new work.

## Not claimed

- Not a vendor stitcher (no Insta360 Studio / `.insv` dual-fisheye).
- Not an optimized-AI-director claim. Pluggable VLM never writes pixels.
- Native MCPB remains staged/local-only.
- Directory submissions and launch posts remain human residuals.
